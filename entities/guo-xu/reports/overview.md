# 郭老师工作汇报总览

按当前确定的五个关注点持续整理：Matrix-Free 在 PIML 中的应用、GPU 在 PIML 中的应用、Matrix-Free 与 GPU 在 PIML 中的联合应用、目前能够求解的问题规模，以及能否在团队软件代码框架下运行。每次汇报说明已经做到什么、对应证据和下一步要解决什么。

本页汇总已有记录，不代表重新运行后的验收结果。具体实验见 [[piml-gpu-matrix-free-demo/report|小型 Demo 汇报]]，完整任务安排见 [[../../../research/piml-matrix-free-gpu/project-plan|项目计划]]。

## 1. Matrix-Free 在 PIML 应用中的进展

已将 PIML 预测的形函数通过变分构造转为局部刚度，并用于全局接口算子的 Matrix-Free 作用与 CG 求解，无需组装全局接口刚度矩阵。

已有二维 24 子结构、574 个接口自由度算例：PyTorch Matrix-Free MatVec 与对应显式路径的相对差为 $3.40\times10^{-16}$，CG 迭代 341 步，真相对残差为 $8.69\times10^{-11}$。这里的算子一致性与残差针对对应的 PIML 离散系统，不等于相对于精确有限元系统的误差；位移与柔顺度误差另见 [[piml-gpu-matrix-free-demo/report#2. 对照结果|精度对照]]。

下一步重点是预条件子、精确系统真残差复核，以及子结构 PIML–Matrix-Free 完整拓扑优化。当前属于保存局部矩阵的路径，不据此称为严格 fully matrix-free。

## 2. GPU 在 PIML 应用中的进展

已开展三维 PIML 批量预测与变分刚度构造。小型 Demo 汇报记录：RTX 5080 上批量为 24–384 个子结构时，单步耗时为 $0.237$–$4.325\,\mathrm{ms}$，相对同一 PyTorch CPU 计算链加速 $20.3$–$29.2$ 倍。

该结果衡量局部预测与构造，不包含完整全局求解或拓扑优化。项目计划保留了另一组耗时与加速比，CPU 线程配置也待核实；正式汇报性能数字前，应统一原始运行记录、计时范围和 CPU 配置，不能混用两组结果。

下一步重点是明确训练与推理设备、数据传输、局部构造和全局求解各自的耗时与峰值显存。

## 3. Matrix-Free + GPU 在 PIML 应用中的进展

目前分别具备 PIML–Matrix-Free 求解验证和 GPU 局部批量计算结果。二维求解与三维 GPU 批处理尚未纳入同一次端到端计时，因此当前可汇报为“模块化小型 Demo 已验证”，尚不能给出三者联合的完整流程加速比。

下一步需要在同一算例中贯通 GPU 上的预测、局部算子作用、gather/scatter、归约和 Krylov 求解，再比较精确组装、精确 Matrix-Free、PIML 组装与 PIML Matrix-Free 四条路径的精度、时间和显存。随后接入密度更新，形成完整拓扑优化流程。

## 4. 目前能求解多大规模的问题

规模须同时说明计算路径和完成环节。以下为已有文档记录的规模，不代表硬件容量上限。

| 路径与完成环节 | 已记录规模 | 当前可说明的能力与边界 |
|---|---|---|
| PIML–Matrix-Free 单次结构分析 | 二维 24 子结构、574 个接口自由度 | 已有 MatVec 与 CG 对照；细网格单元数及全场自由度待从原始产物补齐 |
| PIML GPU 局部批处理 | 三维 24–384 个子结构 | 说明批处理规模，不能视为已完成同规模全局求解 |
| PIML 角点线性迹拓扑优化 | 二维 24 子结构、三维 48 个 Hex8 子结构 | 项目计划记录已有闭环；采用 CPU 显式宏观求解，不代表 Matrix-Free + GPU 闭环，当前可重放状态待核实 |
| 精确有限元 GPU 结构分析基线 | 1,604,043 个自由度 | 项目计划记录的多后端求解结果；不包含 PIML，不能作为 PIML 规模成果 |
| PIML + Matrix-Free + GPU 完整拓扑优化 | 尚无统一验证规模 | 需完成同一算例的全流程验证后报数 |

因此，目前 PIML–Matrix-Free 的明确求解记录是 24 子结构的小规模问题；百万自由度结果属于精确有限元 GPU 基线。更大 PIML 问题的可解规模仍需实测。

后续每项规模结果统一记录：二维/三维、细网格单元数与自由度、子结构数与接口自由度、硬件、求解或优化是否完成、误差与残差、总耗时及峰值内存/显存。最大成功规模与因内存或收敛失败的规模分别记录。

## 5. 在团队软件代码框架下运行
