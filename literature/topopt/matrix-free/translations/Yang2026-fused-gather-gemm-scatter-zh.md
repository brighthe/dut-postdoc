# 摘要

Matrix-free（无矩阵）的 gather–batched-GEMM–scatter 计算模式消除了三维 SIMP 拓扑优化中的全局刚度矩阵装配，但传统的三阶段实现方式在各阶段之间引入了无法避免的显存（DRAM）访存开销。本文提出了一种通过 CuPy 运行时编译接口实现的单一融合 CUDA 核函数（fused CUDA kernel），在单次遍历中一并完成 gather、单元刚度乘法与 scatter 累加。在单张 RTX 4090（24 GB）显卡上，对于包含 21.6 万至 490 万个单元的悬臂梁算例，融合路径实现了随问题规模而变的 4.6–7.3 倍端到端 SIMP 墙钟时间加速比，并在包含 499,125 个单元的扭转基准算例上达到 4.4 倍加速比。与相同精度的 FP32 三阶段基线相比，融合路径在悬臂梁算例上仍可获得 2.3–4.6 倍加速，在扭转算例上获得 2.8 倍加速。针对悬臂梁算子的独立 CUDA-event 测量显示，每次矩阵向量乘（matvec）调用的加速比达到 8.9–13.8 倍；而在 21.6 万和 100 万单元下的板卡实测功耗采样表明，相比于匹配的 FP64 运行，能耗降低了 3.2–4.9 倍。针对桥梁算子的单独压力测试表明，在分布载荷工况下表现出相同的 FP32 与 FP64 三阶段基线趋势（未汇报桥梁算例的直接融合核函数基准数据）。此外，我们评估了 BF16 WMMA 变体：针对匹配张量形状的独立 PyTorch BF16 GEMM 代理获得了 14.3 倍加速，但在 64k–512k 均匀密度测试状态下的直接条件数估计为 $6.1\times 10^5 \text{–} 2.3\times 10^6$，意味着 BF16 条件数乘积达到 $2.4\times 10^3 \text{–} 9.1\times 10^3$，远超 256 的理论阈值，并在所测试的两个内层容差下均观察到了 BF16 迭代重细化（iterative refinement）停滞现象。

**关键词**：拓扑优化（Topology optimization）；SIMP（SIMP）；Matrix-free 有限元（Matrix-free FEM）；GPU 核函数融合（GPU kernel fusion）；BF16 张量核心（BF16 tensor cores）；混合精度（Mixed precision）；迭代重细化（Iterative refinement）；共轭梯度法（Conjugate gradient）；CuPy（CuPy）

# 1 引言

拓扑优化（Topology Optimization, TO）是轻量化结构工程中的经典计算设计方法：在给定的设计域、边界条件以及目标体积分数下，通过优化材料空间分布以最小化结构柔顺度（或其他目标函数），同时满足静力平衡和体积约束。采用固体各向同性材料惩罚微结构（Solid Isotropic Material with Penalization, SIMP）方法 [1–3] 已成为三维结构拓扑优化的标准格式，因为该方法具有简洁的交替更新循环——在有限元分析（FEA）求解、灵敏度分析以及优化准则（Optimality Criteria, OC）密度更新之间迭代推进——只要线性代数方程组能够高效求解，该流程即可扩展至数百万单元规模 [4, 5]。GPU 是加速该循环的天然硬件算力平台：有限元装配与矩阵向量乘（matvec）运算在单元维度具有天然的易并行性（embarrassingly parallel），灵敏度计算与 OC 更新属于逐单元局部操作，而迭代共轭梯度（Conjugate Gradient, CG）求解器可直接映射至 CUDA 原生的大规模并行向量操作模型。

既有关于 GPU 加速拓扑优化的研究工作已经展示了该方法在更大计算规模下的可行性 [6–12]，但一直受到显式稀疏刚度矩阵装配巨大显存开销的制约。对于三线性八节点六面体（Q1）单元，全局刚度矩阵 $\boldsymbol{K}$ 包含 $576 n_{\text{elem}}$ 个单元级局部贡献；因此，当在标准消费级 NVIDIA RTX 4090 GPU 上包含矩阵数值、列索引以及临时装配缓冲区后，显式稀疏装配在数百万单元级别就会撞上显存容量瓶颈（VRAM wall）。本文研究的无矩阵（matrix-free）基线通过采用逐单元评估的无矩阵算子 $\boldsymbol{K}\boldsymbol{v}$ 替代全局显式装配来解决该显存壁垒问题，在不显式形成全局 $\boldsymbol{K}$ 的前提下评估矩阵向量乘积，从而使贯穿本文的单 GPU Python/CuPy 工作流成为可能，并避免了在百万单元尺度下原本会占据主导地位的装配后压缩稀疏行（CSR）显存占用 [13]。这一技术路线与近期在 GPU 和 CPU 平台上开展的无矩阵拓扑优化实现高度一致 [12, 14]。

该无矩阵基线实现将每次矩阵向量乘拆解为三个连续调用的 CUDA 核函数：
1. **收集（Gather）**：根据预先计算的自由度索引表，从全局位移向量中读取各单元对应的自由度数值；
2. **批处理通用矩阵乘法（Batched GEMM）**：利用 CuPy 的批处理矩阵乘法路径（底层调度 cuBLAS）对全部单元并发施加缩放后的单元刚度矩阵；
3. **分散（Scatter）**：利用原子累加规约将各单元计算得到的节点力贡献写回全局输出向量中。

尽管这种三阶段设计实现直观，但其浪费了宝贵的显存带宽：由 Gather 阶段生成并由 Scatter 阶段消耗的中间逐单元局部数组，必须在两次核函数启动之间经过板载显存（DRAM）中转，使得每次矩阵向量乘调用都会额外增加两次完整的 DRAM 数据往返（round-trips）。

### 核函数融合机遇

Roofline 性能模型 [15] 表明，显存带宽是 gather–GEMM–scatter 计算模式的核心性能约束瓶颈：三线性六面体单元矩阵向量乘的计算强度（arithmetic intensity）约为 $3\text{–}6$ FLOP/B，远低于 RTX 4090 显卡上 FP32 单精度的脊点（ridge point，82 FLOP/B）。在这一带宽受限（memory-bound）计算区间内，主要计算开销不是浮点运算指令，而是板载 DRAM 的数据往返。核函数融合（Kernel fusion）——将上述三个阶段合并至单一的 CUDA 核函数启动中，并将中间数据全部保留在线程寄存器和片上共享内存（shared memory）内——可直接消除这些不必要的 DRAM 数据往返。对于规则网格，各单元的基准单元刚度矩阵 $\boldsymbol{K}_e^{\text{unit}}$（$24 \times 24 = 576$ 个浮点数，在共享内存中仅占 2.25 kB）完全一致，每个线程块仅需协同广播加载一次至共享内存，因此线程块内处理的所有单元在执行逐单元矩阵向量乘时，均可直接从片上共享内存读取 $\boldsymbol{K}_e^{\text{unit}}$，而无需反复访问全局 DRAM。理论上，核函数融合可使单元数据在 DRAM 通路上的访存流量降低约 $2\times$（计入索引和密度读取后约降低 $1.8\times$）；而在实际运行中，由于将三次核函数启动开销坍缩为单次启动，实测端到端加速比往往还会进一步超出该理论因子。

### 张量核心作为下一前沿与精度壁垒

NVIDIA 的 Ada Lovelace 架构（RTX 4090）通过 WMMA（Warp-Level Matrix Multiply–Accumulate）API 提供了 BF16 张量核心（Tensor Cores），其 BF16 理论峰值算力高达 165.2 TFLOP/s，相比 FP32 CUDA 核心的 82.6 TFLOP/s 具有 $2\times$ 的硬件理论吞吐优势 [16]。此前在科学计算和混合精度求解器研究中，张量核心已被广泛考察，既验证了其巨大算力潜力，也揭示了其在深度学习之外应用时不可忽视的数值行为问题 [17–19]。对于融合核函数核心的 $24 \times 24$ 逐单元稠密 GEMM，相较于双精度 FP64 批处理 DGEMM，BF16 WMMA 带来了在 GEMM 阶段获得大幅硬件加速的广阔前景。

然而，BF16 仅具有 7 位尾数（在 Carson–Higham 约定下，单位舍入误差 $\varepsilon_{\text{BF16}} = 2^{-8} \approx 3.9 \times 10^{-3}$），这引发了一个根本性问题：当该低精度用于求解 SIMP 刚度方程组的共轭梯度法（CG）时，其数值精度是否充足？在拓扑优化中，随着 SIMP 惩罚指数增大和材料密度对比度急剧上升，全局刚度矩阵的条件数极易超过 BF16 的数值稳定阈值。经典迭代重细化（Iterative Refinement, IR）框架与后续混合精度求解器文献 [20–22] 给出了标准收敛充分条件：

$$
\varepsilon_{\text{BF16}} \cdot \kappa(\boldsymbol{K}) < 1 \iff \kappa(\boldsymbol{K}) < 256.
$$

我们以此作为保守的参考阈值。在本文梳理的文献中，尚未发现有研究在基于密度的连续体三维拓扑优化背景下对这一理论预测进行直接实测检验，也未见在单 GPU 上将 BF16 张量核心与基于密度的三维 SIMP 拓扑优化相结合的报道。

### 主要贡献

本文做出以下四项核心贡献：
1. **单一融合 CUDA 核函数**：设计并实现了单一融合 gather–GEMM–scatter CUDA 核函数（算法 1），有效削减片外显存访存量。在纯算子微基准测试中，相比 FP64 三阶段基线实现 $6.0\text{–}6.6\times$ 的每步 matvec 加速比；在实际悬臂梁算子独立 CUDA-event 测量下达到 $8.9\text{–}13.8\times$ 加速（反映了将三次 API 调度开销合并为单次启动所避免的额外 Python/CuPy 调度延迟）。该核函数通过 CuPy 运行时编译接口嵌入，无需独立的离线 CUDA 构建流程。
2. **多载荷工况下的端到端 SIMP 加速**：在 21.6 万至 490 万单元的悬臂梁基准测试中，融合核函数实现了随问题规模而变的 $4.6\text{–}7.3\times$ 端到端 SIMP-120 墙钟时间加速，并在包含 499,125 个单元的三维扭转基准算例上获得 $4.4\times$ 加速。相较于同精度 FP32 三阶段基线，悬臂梁算例仍可获得 $2.3\text{–}4.6\times$ 加速，扭转算例获得 $2.8\times$ 加速。桥梁硬问题压力测试验证了在分布载荷工况下相同的 FP32 与 FP64 性能增益趋势。
3. **BF16 WMMA 吞吐量探针**：实现了面向密度拓扑优化的 CuPy 可调用 BF16 WMMA 矩阵向量乘核函数，并在张量尺寸匹配的独立 PyTorch BF16 GEMM 代理基准测试中录得 $14.3\times$ 加速（相对于 FP64）；同时明确指出了完整融合核函数性能依然受制于 gather/scatter 访存阶段的客观边界。
4. **混合精度收敛性理论与实证分析**：系统剖析了 BF16 应用于 SIMP 刚度矩阵 CG 求解时的标准精度壁垒 $\varepsilon_{\text{BF16}} \cdot \kappa(\boldsymbol{K}) \gtrsim 1$。实测表明在当前 Jacobi 预条件 CG 下 BF16-IR 发生收敛停滞，直接证实了该理论壁垒的存在；进一步指出了将张量核心用于多重网格平滑器（有效条件数由粗网格修正压制在 256 以下）是发挥其算力优势的切实路径。

# 2 相关工作

## 2.1 大规模 GPU 拓扑优化

拓扑优化在 GPU 平台上的发展脉络，本质上反映了求解器体系结构与现代加速器内存层次结构的持续适配演进。早期的 GPU 拓扑优化实现（如 Wadbro 与 Berggren [6]）利用像素/体素网格探索了百万像素级规模的求解。随后，Challis 等人 [7] 证明了采用单 GPU 求解高分辨率三维拓扑优化的可行性。随着问题规模向千万级拓展，Martínez-Frutos 与 Herrero-Pérez [8, 9] 构建了多 GPU 并行求解架构，将区域分解与 Krylov 迭代求解器相结合以突破单卡内存限制。

在 Python 与高级科学计算生态中，Hou 等人 [10] 利用 CuPy 和向量化稀疏矩阵向量乘（SpMV）展示了单 GPU 上高效的大规模拓扑优化，但显式稀疏矩阵存储（CSR 格式）依然在单元数超过两百万时受制于 GPU 显存墙。Qi 等人 [11] 针对连续纤维增强复合结构开发了专用 GPU 拓扑优化求解器。Träff 等人 [12] 提出了基于 Futhark 函数式并行语言的极简高效 GPU 拓扑优化框架，通过无矩阵表示与多重网格预条件共轭梯度法（MG-CG），在单张 GPU 上完成了超大尺度的拓扑优化计算。

## 2.2 GPU 上的 Matrix-Free 有限元算子

无矩阵有限元方法通过在算子评估时在线重新计算局部刚度贡献，彻底摆脱了装配与存储全局刚度矩阵的高昂内存开销，因而在现代高吞吐、显存受限的 GPU 架构上引起了高度重视。以百亿亿次级计算（Exascale Computing Project, ECP）的 CEED 联合项目为代表 [52]，无矩阵算子分解被形式化为限制（restriction）、基函数评估（basis）与正交点函数（Q-Function）的标准流水线，并在 libCEED、MFEM 以及 deal.II 等主流高性能有限元软件中得到广泛验证 [23–25]。

在拓扑优化的具体场景下，Träff 等人 [12] 将无矩阵算子引入 GPU 连续体优化；Wang 等人 [14] 近期发布了面向大规模三维拓扑优化的教学型无矩阵 MATLAB 代码（TOP3D_XL），系统阐明了规则直角六面体网格上基于单元作用（Element-by-Element, EbE）与共享参考单元矩阵的数据复用优势。与通用高阶非结构网格有限元相比，基于均匀网格的拓扑优化算子具有几何形状高度规则、所有单元共享唯一标准单刚的独特性质，为进一步消除中间内存流量提供了明确的结构化切入点。

## 2.3 访存密集型 GPU 核函数的核函数融合

GPU 核函数融合（Kernel Fusion）是提升低计算强度、访存受限算法性能的通用系统优化技术。其核心思想是将多个顺序启动的核函数合并为单一核函数，使前一阶段产生的数据留在片上寄存器或共享内存中直接被后一阶段消费，避免跨核函数的板载 DRAM 往返读写。例如，Filipovič 等人 [36] 在通用线性代数流水线中证明融合可带来高达 $2.6\times$ 的加速。Wahib 与 Maruyama [37, 38] 针对生产级 CFD 与天气预报代码构建了模板（stencil）核函数的端到端融合框架，消除了大量无谓的 DRAM 流量，获得了 $1.2\text{–}1.75\times$ 的端到端加速。Halide 语言 [39] 通过将算法与调度解耦，建立了融合与重计算权衡的形式化框架。

然而，本文研究的无矩阵有限元算子与上述经典文献中的计算模式存在显著差异：
1. **收集阶段（Gather）** 需要通过全局非规则自由度索引映射表（`edof`）间接寻址读取全局向量；
2. **GEMM 阶段** 是对每个单元独立的 $24 \times 24$ 稠密对称矩阵乘以局部向量，并乘以随物理场演化的单元密度标量；
3. **分散阶段（Scatter）** 需要向全局非规则输出向量执行跨单元共享节点的原子累加规约（Atomic-add reduction）。

在既有的自动化融合编译器文献中，尚无现成框架能够原生兼顾这种复杂的间接访存与原子累加混合流水线。因此，本文采用 CUDA C 手工编写融合核函数，并通过 CuPy 的 NVRTC 接口进行运行时即时编译与内联嵌入。Träff 等人 [12] 的 Futhark 方案虽然由编译器在编译期隐式完成了类似的 gather–contract–scatter 模式融合，但本文在 CUDA C 层面显式实现并优化了该流水线，并将其扩展至 BF16 WMMA 张量核心与混合精度收敛性理论验证。

## 2.4 迭代求解器中的混合精度与张量核心

混合精度迭代重细化（Mixed-Precision Iterative Refinement, IR）的现代数学基础由 Carson 与 Higham [20] 奠定，他们给出了基于工作精度单位舍入误差与问题条件数的三精度 IR 收敛充分条件与误差上界。Higham 与 Mary [21] 进一步系统综述了数值线性代数中的混合精度算法，界定了 FP16 与 BF16 安全加速矩阵分解与迭代求解的工况区间。Amestoy 等人 [40] 提出了五精度 GMRES-IR 框架，通过构建由低精度内层求解构成的级联体系实现了高精度逼近。

在专用硬件加速层面，Markidis 等人 [17] 在 NVIDIA 张量核心面世初期便对其在非机器学习科学计算中的可编程性、性能与精度进行了基准测试。Fasi 等人 [18] 深入测试了 V100、T4 和 A100 张量核心的舍入模式、次正规数处理及累加次序，表明其微体系结构行为存在微妙偏离 IEEE 754 标准的现象。Henry、Tang 与 Heinecke [22] 重点倡导将 BF16 应用于高性能计算迭代求解器，并乐观预测在 FP32 外层迭代重细化框架下 BF16 可在“很大条件数范围”内收敛。Kalamkar 等人 [41] 明确了 BF16 格式兼具 7 位尾数与 FP32 动态范围的数学特性。

在求解器工程应用上，Haidar 等人 [19] 在 MAGMA 框架下利用 V100 的 FP16 张量核心与 FP32 累加实现了稠密线性方程组相对 FP64 达 $4\times$ 的加速。Clark 等人 [42] 证明在格点量子色动力学（Lattice QCD）中采用混合精度 Krylov 求解器能够达到工业级仿真精度。McCormick、Benzaken 与 Tamstorf [43] 为对称正定椭圆型方程的混合精度多重网格求解器建立了严谨的代数误差分析框架。近期，Bai、Ootomo 与 Yokota [44] 提出了在 GPU 上运行的瓦片粒度（tile-grained）混合精度单核 CG 求解器（Mille-feuille）。本文的贡献在于将 BF16 混合精度分析深入推进至拓扑优化应用场景：实测发现，尽管在 512k 规模下单步 GEMM 代理可获得 $14.3\times$ 加速，但经典迭代重细化在此类工程 PDE 系统中彻底停滞，原因在于直接幂法实测条件数 $\kappa(\boldsymbol{K}) \approx 6.1 \times 10^5 \text{–} 2.3 \times 10^6$ 跨越了测试网格规模（64k–512k 单元），使得乘积 $\varepsilon_{\text{BF16}} \cdot \kappa \approx 2.4 \times 10^3 \text{–} 9.1 \times 10^3$，极度越过了 Carson–Higham 判据给出的理论收敛门槛 256。

## 2.5 面向 PDE 与有限元计算的张量核心

除标准稠密矩阵运算外，研究人员发展了多种将传统偏微分方程算子重构映射至张量核心的方法。Dakkak 等人 [45] 证明任意并行规约与前缀和扫描均可改写为 WMMA 操作，性能较传统规约核函数提升可达两个数量级。Ootomo 与 Yokota [46] 提出了分拆 FP16（split-FP16）补偿机制，从支持 FP32 累加的 FP16 WMMA 中找回单精度精度；进一步利用 INT8 整数张量核心模拟实现了双精度 DGEMM [47]。在网格模板计算方面，ConvStencil [48] 基于 im2col 展开重塑模板数据，LoRAStencil [49] 则采用低秩矩阵逼近将空间差分转化为张量核心矩阵乘法。

针对有限元张量积算子，Cui [50] 探索了通过专用张量核心布局加速高阶有限元张量积运算的有效路径。本文与既有工作的关键区别在于：本文直接针对密度拓扑优化中三线性八节点六面体单元的 $24 \times 24$ 单元刚度乘算子，采用 BF16 WMMA 分块完成硬件加速，并深入剖析其与 Krylov 子空间求解器耦合时的收敛性边界。

## 2.6 预条件子差距与未来研究路径

在 SIMP 拓扑优化的每个设计步中，线性方程组求解的 CG 迭代步数主要取决于所采用的预条件子，这直接主导了整个优化过程的绝对墙钟时间。Jacobi（对角线）预条件子是最简便的选择——完全天然并行且构建开销极低，但其所需的 CG 迭代步数随条件数平方根呈 $O(\sqrt{\kappa(\boldsymbol{K})})$ 增长。对于标准悬臂梁算例，Jacobi 预条件子在本文实现中每步需数十至数百次迭代；对于扭转（torsion）等刚度剪切主导的难算例，则极易达到设定的 1,000 步上限；而在具有准刚体位移奇异模态的三维 MBB 梁算例中，简单 Jacobi 预条件子甚至完全无法保证物理位移的正确收敛。

Amir、Aage 与 Lazarov [51] 指出多重网格预条件共轭梯度法（MG-CG）能大幅压缩三维 SIMP 问题的单步求解次数，且几何网格层级可在设计步之间复用。Träff 等人 [12] 采用在 V-cycle 内结合 SSOR 平滑的预条件策略，完成了高达 6550 万单元的超大规模求解。Peetz 与 Elbanna [52] 系统比较了代数多重网格（AMG）与几何多重网格（GMG）在三维拓扑优化中的权衡，表明 GMG 具有单步耗时短的显著优势。McCormick 等人 [43] 给出的椭圆算子混合精度多重网格代数理论，为固定网格几何层级下的加速提供了数学支撑。这些前序成果清晰勾勒了当前以 Jacobi 预条件为代表的独立核函数求解器的局限性，并为第 5 节提出的将融合张量核心作为几何多重网格平滑器的后续架构奠定了基础。

# 3 方法

## 3.1 三维 SIMP 拓扑优化

考虑在由 $n_{\text{elem}}$ 个三线性八节点六面体（Q1）单元构成的固定笛卡尔网格上的经典线弹性最小柔顺度拓扑优化问题：

$$
\begin{aligned}
\min_{\boldsymbol{\rho}} \quad & c(\boldsymbol{\rho}) = \boldsymbol{f}^\top \boldsymbol{u}(\boldsymbol{\rho}) = \boldsymbol{u}^\top \boldsymbol{K}(\boldsymbol{\rho}) \boldsymbol{u} \\
\text{s.t.} \quad & \boldsymbol{K}(\boldsymbol{\rho}) \boldsymbol{u} = \boldsymbol{f}, \\
& \frac{1}{n_{\text{elem}}} \sum_{e=1}^{n_{\text{elem}}} \rho_e = V_f, \\
& 0 < \rho_{\min} \le \rho_e \le 1,
\end{aligned}
\tag{1}
$$

式中，$\boldsymbol{f} \in \mathbb{R}^{n_{\text{dof}}}$ 为外部外载荷向量，$\boldsymbol{u} \in \mathbb{R}^{n_{\text{dof}}}$ 为整体节点位移向量，$V_f$ 为预设的目标体积分数上限，$\rho_e$ 为单元 $e$ 的设计密度。全局刚度矩阵 $\boldsymbol{K}(\boldsymbol{\rho})$ 基于经典 SIMP 材料插值模型 [1] 由单元刚度贡献累加而成：

$$
\boldsymbol{K}(\boldsymbol{\rho}) = \sum_{e=1}^{n_{\text{elem}}} \boldsymbol{B}_e^\top \left[ \rho_{\min} + (1 - \rho_{\min}) \rho_e^p \right] \boldsymbol{K}_e^{\text{unit}} \boldsymbol{B}_e,
\tag{2}
$$

式中，$\boldsymbol{B}_e \in \{0, 1\}^{24 \times n_{\text{dof}}}$ 为从全局向量提取单元 24 个局部自由度的布尔收集/分散算子，$\boldsymbol{K}_e^{\text{unit}} \in \mathbb{R}^{24 \times 24}$ 为基准单位弹性模量下的各向同性线弹性单元刚度矩阵，$p$ 为材料惩罚指数（基准测试中常取 $p = 3$），$\rho_{\min} = 10^{-9}$ 为用于避免空洞区域刚度奇异的数值下限。

为抑制网格依赖性与棋盘格现象，采用标准三场正则化流程 [26, 53, 54]：原始设计变量 $\rho_e$ 首先经截断锥形滤波器（滤波半径为 $r_{\min}$）加权平滑得到滤波密度 $\bar{\rho}_e$，随后输入双曲正切光滑 Heaviside 投影函数映射为物理密度 $\tilde{\rho}_e$：

$$
\tilde{\rho}_e = \frac{\tanh(\beta \eta) + \tanh(\beta(\bar{\rho}_e - \eta))}{\tanh(\beta \eta) + \tanh(\beta(1 - \eta))},
\tag{3}
$$

式中，投影阈值固定为 $\eta = 0.5$，陡度参数 $\beta$ 在优化进程中按预定连续化策略逐步倍增。目标函数的解析灵敏度 $\partial c / \partial \rho_e$ 通过伴随法推导，并在各 SIMP 步中由结合二分法的准则更新法则（Optimality Criteria, OC）[3] 执行设计更新。优化过程中的设计离散程度通过无量纲灰度指标（grayness metric）量化：

$$
g = \frac{4}{n_{\text{elem}}} \sum_{e=1}^{n_{\text{elem}}} \rho_e (1 - \rho_e),
$$

当 $g = 0$ 时表示构型完全呈现二值化（0–1 清晰分布），数值越大则表明中间过渡密度区域占比越高。

## 3.2 Matrix-Free $Kv$ 算子：三阶段基线

在大规模三维计算中，直接在显存中装配与存储全局刚度矩阵 $\boldsymbol{K}$ 的 CSR 格式存在不可逾越的显存墙：对于三线性六面体网格，每个单元贡献 $24 \times 24 = 576$ 个非零元，仅行指针与列索引数组在百万单元量级就需占用数千兆字节显存，在包含装配缓冲区后极易击穿单张 RTX 4090 的 24 GB 限制。为此，无矩阵有限元方法在评估矩阵向量乘积 $\boldsymbol{w} \leftarrow \boldsymbol{K}\boldsymbol{v}$ 时完全不显式形成全局刚度矩阵，而是通过逐单元局部矩阵乘后直接写回实现：

$$
\boldsymbol{w} = \boldsymbol{K}\boldsymbol{v} = \sum_{e=1}^{n_{\text{elem}}} \boldsymbol{B}_e^\top \left[ \rho_{\min} + (1 - \rho_{\min}) \rho_e^p \right] \boldsymbol{K}_e^{\text{unit}} \boldsymbol{B}_e \boldsymbol{v}.
\tag{4}
$$

未融合的传统 Python/CuPy 基线实现将式 (4) 分解为三个严格依赖的连续 CUDA 核函数调用：
- **阶段 1（Gather，收集）**：对每个单元 $e$，基于预计算的自由度索引映射表 $\text{edof} \in \mathbb{Z}^{n_{\text{elem}} \times 24}$，从全局向量 $\boldsymbol{v}$ 中提取对应的 24 维局部自由度向量 $\boldsymbol{u}_e = \boldsymbol{v}[\text{edof}_e] \in \mathbb{R}^{24}$，写入中间工作数组 `uelem`；
- **阶段 2（Batched GEMM，批处理矩阵乘）**：通过 CuPy 批处理矩阵乘路径（调度底层 cuBLAS），在全部 $n_{\text{elem}}$ 个单元上并行计算缩放刚度力 $\boldsymbol{f}_e = \left[\rho_{\min} + (1 - \rho_{\min})\rho_e^p\right] \boldsymbol{K}_e^{\text{unit}} \boldsymbol{u}_e$，写入中间工作数组 `felem`；
- **阶段 3（Scatter，分散累加）**：调用直方图规约核函数，通过原子累加将 $\boldsymbol{f}_e$ 写回全局输出向量 $\boldsymbol{w}[\text{edof}_e] \mathrel{+}= \boldsymbol{f}_e$。

该三阶段分解导致每次矩阵向量乘必须执行三次完整的显存往返：Gather 写入局部向量 `uelem`，GEMM 重新读入 `uelem` 并写出 `felem`，Scatter 再次读入 `felem` 并原子累加回全局显存。以双精度 FP64 为例，两个中间临时数组在 200 万单元规模下合计需占用 $2 \times (24 \times 2 \times 10^6 \times 8) \text{ 字节} = 768 \text{ MB}$。更为严重的是，这些巨大的中间缓冲区跨核函数频繁换出至板载 DRAM，使得算子完全陷入严重的访存带宽瓶颈。

## 3.3 融合 Gather–GEMM–Scatter 核函数

融合核函数的核心思想是将 Gather、GEMM 与 Scatter 的全流程封装进单个 CUDA 核函数中，使单元的局部中间位移与节点力完全驻留在线程私有的寄存器与块内共享内存中，彻底消减向板载 DRAM 写入和重新读取中间数组的过程。

实现中采用“每个有限元对应一个线程”的映射策略，每个线程块配置 128 个线程。因此，针对具有 $n_{\text{elem}}$ 个单元的网格，核函数的执行配置为 $(\lceil n_{\text{elem}} / 128 \rceil, 1, 1)$ 线程块 $\times (128, 1, 1)$ 线程。具体算法逻辑如算法 1 所示。

```
算法 1 融合 Gather–GEMM–Scatter CUDA 核函数（单线程执行逻辑）
输入: edof[nelem, 24], v[ndof], Kunit[24, 24], ρ[nelem], p, ρmin
输出: w[ndof] (全局原子累加写入)
 1: e ← (blockIdx.x) · (blockDim.x) + threadIdx.x
 2: if e ≥ nelem then
 3:     return
 4: end if
 5: 片上共享内存: 线程块内协同协作广播加载 Kunit[24, 24] 至 __shared__ 数组
 6: __syncthreads()
 7: ke ← ρmin + (1 - ρmin) · (ρ[e])^p               ▷ 单元 SIMP 刚度缩放因子
 8: 寄存器 Gather: 局部数组 u[j] ← v[edof[e, j]],  j = 0, ..., 23
 9: for i = 0 to 23 do
10:     fi ← 0.0
11:     for j = 0 to 23 do
12:         fi += ke · Kunit[i, j] · u[j]           ▷ 直接从共享内存读取 Kunit
13:     end for
14:     atomicAdd(&w[edof[e, i]], fi)               ▷ 全局 Scatter 原子累加
15: end for
```

### 共享内存数据复用

对于规则结构化网格，单元基准刚度矩阵 $\boldsymbol{K}_e^{\text{unit}} \in \mathbb{R}^{24 \times 24}$ 仅取决于单元物理尺寸与各向同性泊松比，其数值对于全场所有六面体单元均严格恒定。在单精度 FP32 下，该矩阵仅占 $24 \times 24 \times 4 \text{ 字节} = 2.25 \text{ kB}$，极其轻量。融合核函数在执行主循环前，由线程块内的 128 个线程协同将其一次性载入片上共享内存（`__shared__`）。在随后的局部 GEMM 循环中，块内所有线程均直接从共享内存并发读取该常数单刚的各行，相较于反复访问全局内存，片上带宽复用倍数高达 24 倍。

### 显存流量对比分析

定义每次矩阵向量乘调用中平均每个单元在板载 DRAM 上产生的总传输字节数为 $B$。对于未融合的三阶段基线（双精度 FP64）：

$$
B_{\text{baseline}} = \underbrace{24 \cdot 8}_{\text{Gather 写出}} + \underbrace{24 \cdot 8}_{\text{GEMM 读入}} + \underbrace{24 \cdot 8}_{\text{GEMM 写出}} + \underbrace{24 \cdot 8}_{\text{Scatter 读入}} = 768 \text{ 字节/单元}.
\tag{5}
$$

融合核函数完全消除了这中间两次完整的 DRAM 往返缓冲，其仅需从全局显存读取节点位移并直接原子写回全局节点力：

$$
B_{\text{fused}} = \underbrace{24 \cdot 8}_{\text{Gather 全局读}} + \underbrace{24 \cdot 8}_{\text{Scatter 全局原子写}} = 384 \text{ 字节/单元},
\tag{6}
$$

这带来了单元浮点数据在板载 DRAM 传输上严格 $2\times$ 的理论降幅。若进一步计入读取索引表 `edof`（$24 \times 4 = 96$ 字节/单元）与密度数组 $\boldsymbol{\rho}$（$4$ 字节/单元），理论访存总量由基线的约 868 字节/单元降低至融合核函数的约 480 字节/单元，理论压缩比仍达 $1.8\times$。在实际运行中，GPU 的 L2 Cache 能够进一步平滑部分共享节点的索引与位移访问，实测所表现出的加速比明显超越了纯 DRAM 访存压缩因子。

### CuPy 运行时编译（NVRTC）

融合核函数的 CUDA C 代码以源码字符串形式直接内嵌于 Python 脚本中，在首次调用时通过 CuPy 提供的运行时编译接口调用 NVRTC（NVIDIA Runtime Compilation）自动完成动态编译与 GPU 二进制加载，全程无需配置独立的 Makefile、CMake 或离线 nvcc 构建链。代码量仅约 80 行，兼具了 Python 原生工作流的极简性与 CUDA 原生 C++ 的底层执行性能。

## 3.4 BF16 WMMA 张量核心变体

现代 NVIDIA GPU 架构通过 WMMA（Warp-Level Matrix Multiply–Accumulate）指令集暴露张量核心算力，支持在硬件层面执行矩阵分块乘加计算 $\boldsymbol{C} \leftarrow \boldsymbol{A}\boldsymbol{B} + \boldsymbol{C}$。在 Ada Lovelace 架构的 RTX 4090 显卡上，硬件原生支持的 BF16 WMMA 分块规格为 $16 \times 16 \times 16$（即 $m=16, n=16, k=16$），累加至单精度 FP32。BF16 格式由 1 位符号位、8 位指数位与 7 位尾数位组成，保持了与 FP32 完全相同的动态数值范围，其理论硬件吞吐为 165.2 TFLOP/s，是同架构单精度 CUDA 核心（82.6 TFLOP/s）的整整两倍 [16]。

### 张量核心分块与填充设计

逐单元刚度阵乘法 $\boldsymbol{f}_e = k_e \boldsymbol{K}_e^{\text{unit}} \boldsymbol{u}_e$ 属于 $24 \times 24$ 矩阵乘以 $24 \times 1$ 向量。由于 WMMA 指令强制要求张量维度必须为 16 的整倍数，本研究设计了如下几何填充策略：
1. 将 $24 \times 24$ 的 $\boldsymbol{K}_e^{\text{unit}}$ 在四周补零扩展至 $32 \times 32$ 稠密阵；
2. 将每个单元的 $24 \times 1$ 局部向量填充扩展至 $32 \times 16$，其中前 24 行存放该 warp 负责的 16 个单元对应的位移列向量，后 8 行及无效列全部填充为 0；
3. 每个 CUDA 线程块处理 128 个单元，包含 8 个 warp（每块 256 线程）；每个 warp 独立处理 16 个有限元。

在每个 warp 内部，通过调度 4 次 $16 \times 16 \times 16$ WMMA 乘法覆盖 $32 \times 32$ 的输出空间，实现单指令流下同时计算 16 个单元的局部刚度乘积。SIMP 惩罚因子 $k_e$ 在 WMMA 计算完成后于 FP32 寄存器中相乘，最终分散写回依然采用 FP32 原子累加，以最大限度维持数值精度。

### 内存布局与开销分析

BF16 WMMA 路径要求在载入 WMMA 寄存器片段前，将位移数据与单刚数据就地转换（cast）为 BF16 格式。虽然这一转换引入了微小的格式转换开销，但使张量核心的算力释放成为可能。但值得注意的是，即使在张量核心上 GEMM 阶段实现了理论吞吐倍增，整体无矩阵算子的 Gather 与 Scatter 阶段依旧受制于非规则全局内存访问。

## 3.5 共轭梯度求解器中的 BF16 算术：收敛性分析

为将低精度算子融入高精度求解循环，采用经典的三精度迭代重细化（Iterative Refinement, IR）框架 [20, 22]：

$$
\boldsymbol{r}^{(k)} = \boldsymbol{f} - \boldsymbol{K} \boldsymbol{u}^{(k)} \quad (\text{FP32 外层计算}),
\tag{7}
$$

$$
\boldsymbol{K} \boldsymbol{e}^{(k)} = \boldsymbol{r}^{(k)} \quad (\text{BF16 内层 CG 求解}),
\tag{8}
$$

$$
\boldsymbol{u}^{(k+1)} = \boldsymbol{u}^{(k)} + \boldsymbol{e}^{(k)} \quad (\text{FP32 状态更新}).
\tag{9}
$$

### 理论收敛边界

根据 Carson 与 Higham 的严格分析 [20]，迭代重细化收敛要求内层工作精度的单位舍入误差 $\varepsilon$ 与系统矩阵条件数 $\kappa(\boldsymbol{K})$ 的乘积必须严格小于 1。对于 BF16 格式，尾数仅有 7 位，其有效单位舍入误差 $\varepsilon_{\text{BF16}} = 2^{-8} \approx 3.9 \times 10^{-3}$，由此推导出保证算法渐近收敛的充分条件为：

$$
\varepsilon_{\text{BF16}} \cdot \kappa(\boldsymbol{K}) < 1 \iff \kappa(\boldsymbol{K}) < \frac{1}{\varepsilon_{\text{BF16}}} \approx 256.
\tag{10}
$$

### 拓扑优化中的精度壁垒

在三维 SIMP 拓扑优化中，随着惩罚指数 $p$ 增加以及固体（$\rho_e = 1$）与近似空洞（$\rho_e \approx \rho_{\min} = 10^{-9}$）材料对比度的建立，全局刚度矩阵的理论条件数随 $1 / \rho_{\min}^p$ 呈现爆炸式增长。即便在优化初始的均匀密度分布状态（$\rho = 0.5$），通过本文第 4.8 节实施的无矩阵幂法与反幂法实测得到的刚度矩阵条件数也高达：
- 64k 单元：$\kappa(\boldsymbol{K}) \approx 6.1 \times 10^5$；
- 216k 单元：$\kappa(\boldsymbol{K}) \approx 1.3 \times 10^6$；
- 512k 单元：$\kappa(\boldsymbol{K}) \approx 2.3 \times 10^6$。

对应的条件数乘积达到 $\varepsilon_{\text{BF16}} \cdot \kappa(\boldsymbol{K}) \approx 2.4 \times 10^3 \text{–} 9.1 \times 10^3$，比收敛门槛 256 高出至少一个数量级。因此，BF16 迭代重细化在拓扑优化中面临着刚性的数学精度壁垒，无法作为内层 CG 替代传统浮点求解。

### 未来可行演进路径

尽管 BF16 无法直接胜任全系统的 CG 迭代，但其极高的硬件吞吐优势使其极为适合充当多重网格（Multigrid）算法中的平滑器（Smoother）。在几何多重网格 V-cycle 中，各层平滑器仅负责消除高频误差，系统残差的有效谱半径受粗网格校正严格约束，其等效条件数能够被压制在 256 门槛以内，这为在保证全局数值稳定的前提下充分榨取张量核心算力提供了明确的技术路线。

## 3.6 预条件共轭梯度法与热启动策略

在每个 SIMP 优化迭代步中，全局平衡方程 $\boldsymbol{K}\boldsymbol{u} = \boldsymbol{f}$ 均通过 Jacobi 预条件共轭梯度法（Jacobi-PCG）求解 [55, 56]。Jacobi 对角预条件子 $\boldsymbol{M} = \text{diag}(\boldsymbol{K})$ 借助一次独立的无矩阵循环在 $O(n_{\text{elem}})$ 复杂度内逐单元累加提取，完全无需显式矩阵存储。

- **热启动（Warm-start）**：鉴于拓扑优化进入中后期（约 10–20 步之后）材料分布场演化逐渐平缓，将第 $k$ 步的收敛位移解 $\boldsymbol{u}^{(k)}$ 直接作为第 $k+1$ 步 CG 迭代的初始猜测值 $\boldsymbol{u}^{(k+1)}_0$。基准测试表明，热启动在保持最终收敛精度的同时显著削减了后期的 CG 迭代步数。
- **收敛准则**：求解器以未预条件的相对残差满足 $\|\boldsymbol{r}_k\|_2 / \|\boldsymbol{f}\|_2 \le 10^{-5}$ 或达到设定的最大 1,000 次迭代作为终止判定条件。

## 3.7 Roofline 分析

## 3.8 软件架构

整个三维拓扑优化求解系统基于 Python 3.11 与 CuPy 13 构建，专为单张消费级 GPU 优化，包含以下五个层次：
1. **问题初始化层**：基于 NumPy/CuPy 快速生成结构网格、构建单元自由度映射矩阵（`edof`）、装配边界条件及卷积滤波核；
2. **融合 CUDA 核函数层**：约 80 行 CUDA C 源码内嵌于 Python 中，首次调用由 CuPy NVRTC 即时编译并建立显存常驻二进制缓存；
3. **PCG 迭代求解循环**：纯 Python 结合 CuPy 并行数组操作，将融合核函数封装为函数对象，在 GPU 上闭环执行矩阵向量乘与内积更新；
4. **SIMP 外层优化循环**：在 GPU 上完成伴随灵敏度过滤、Heaviside 双曲正切投影、OC 密度二分更新及收敛性判定；
5. **数据交互与可视化层**：支持在设计步进中仅向 CPU 传输标量柔顺度指标，构型与密度场序列化为 NumPy 数组和 VTK 格式以供后处理渲染。

## 4.1 实验设置

### 硬件环境

所有 GPU 实验均在单张 NVIDIA GeForce RTX 4090 显卡 [16] 上进行（Ada Lovelace 架构；24 GB GDDR6X 显存；1.008 TB/s 理论内存带宽；BF16 / FP32 / FP64 理论算力分别为 165.2 / 82.6 / 1.29 TFLOP/s）。主机系统环境为 Microsoft Windows 10.0.26200.8037，安装 NVIDIA 显卡驱动 595.71。

### 软件生态

求解框架运行于 Python 3.11 环境下，核心依赖包括 CuPy 13.6.0（绑定 CUDA 12.9 运行时）、PyTorch 2.5.1（内置 CUDA 12.1 运行时）、NumPy 2.2.6、SciPy 1.15.3、Matplotlib 3.10.7、scikit-image 0.25.2、Pandas 2.3.3 以及 PyVista 0.46.3。显卡功耗上限保持出厂默认的 450 W。PyTorch 与 CuPy 的 CUDA 运行时版本并存由主机安装的统一 NVIDIA 驱动原生支持；拓扑优化核心求解流程完全基于 CuPy，PyTorch 仅用于热点微基准中对独立的 BF16/FP16 GEMM 代理调用进行基准测时，PyVista 和 scikit-image 仅用于构型三维渲染。

### 基准算例

本研究采用两个主要的定量基准算例（悬臂梁与扭转轴），以及两个 187,500 单元的硬问题压力测试算例（MBB 梁与下承式桥梁）：
- **悬臂梁（Cantilever beam）**：几何设计域为 $2 \times 1 \times 0.5$，左侧整个表面完全固定固支，右侧表面中心点受垂直向下的单位集中载荷。目标体积分数设为 $V_f = 0.30$，初始滤波半径为 $r_{\min} = 1.5$。微基准测试涵盖 64k、216k、512k 及 1M 单元；单次冷启动有限元求解测试覆盖 216k、512k、1M、2M、4.9M 及 8M 单元；端到端 SIMP 扩展性测试包含 216k、512k、1M、2M 及 4.9M 单元。
- **扭转轴基准算例（Torsion benchmark）**：包含 $499,125$ 个单元（网格规格为 $105 \times 105 \times 45$），一端施加扭矩剪切约束，另一端受反向扭转剪切面力，用于测试剪切变形主导、线性代数求解难度极高的应力状态。
- **MBB 梁硬问题压力测试**：$150 \times 50 \times 25 = 187,500$ 单元，几何尺寸 $3 \times 1 \times 0.5$；左边缘施加 $u_x$ 对称约束，点 $(3, 0, 0.25)$ 施加 $u_y$ 支承约束，在载荷点 $(0, 1, 0.25)$ 施加垂直向下单位载荷；$V_f = 0.50$，初始 $r_{\min} = 1.5$。
- **桥梁硬问题压力测试（Bridge benchmark）**：$150 \times 50 \times 25 = 187,500$ 单元，几何尺寸 $3 \times 1 \times 0.5$；底部两端简支，顶部表面受均匀分布的垂直向下压力荷载；$V_f = 0.30$，初始 $r_{\min} = 1.5$。

### 连续化策略与测量约定

在 120 步的标准 SIMP-120 基准测试中，材料惩罚、Heaviside 投影与滤波半径按确定的三阶段退火策略推进：
1. **第 1–40 步**：$p = 3.0, \beta = 8.0, \text{move} = 0.10$，$r_{\min}$ 线性降至 1.35；
2. **第 41–65 步**：$p = 4.5, \beta = 16.0, \text{move} = 0.08$，$r_{\min}$ 线性降至 1.25；
3. **第 66–120 步**：$p = 4.5, \beta = 32.0, \text{move} = 0.05$。

汇总汇报时，采用“选定迭代步（Selected iterate）”准则——即在满足体积约束的优化轨迹中选取柔顺度最低的有效设计步指标，而非简单取最后一步；这避免了优化末期参数剧烈扰动对横向对比的干扰。

## 4.8 条件数估计

为从根源解释 BF16 的停滞机理，采用无矩阵幂法与反幂法对悬臂梁系统刚度矩阵的极值特征值进行测量。在均匀材料初始状态（$\rho = 0.5, p = 3.0$）下测得：
- **64k 单元**：$\lambda_{\max} \approx 2.6 \times 10^3, \lambda_{\min} \approx 4.2 \times 10^{-3} \implies \kappa(\boldsymbol{K}) \approx 6.1 \times 10^5$；
- **216k 单元**：$\lambda_{\max} \approx 2.7 \times 10^3, \lambda_{\min} \approx 2.1 \times 10^{-3} \implies \kappa(\boldsymbol{K}) \approx 1.3 \times 10^6$；
- **512k 单元**：$\lambda_{\max} \approx 2.7 \times 10^3, \lambda_{\min} \approx 1.2 \times 10^{-3} \implies \kappa(\boldsymbol{K}) \approx 2.3 \times 10^6$。

将测得条件数代入判据公式，得到条件数乘积分别为 $\varepsilon_{\text{BF16}} \cdot \kappa \approx 2.4 \times 10^3$（64k）、$5.2 \times 10^3$（216k）与 $9.1 \times 10^3$（512k），均高出理论安全门槛 256 达一至两个数量级，实证了系统处于深度的非收敛区间。

# 5 讨论

## 5.1 加速比趋势解读

融合 gather–GEMM–scatter 核函数在纯算子微基准上实现了 $6.0\text{–}6.6\times$ 的每步矩阵乘加速，并在端到端 SIMP-120 悬臂梁算例上取得了 $4.6\text{–}7.3\times$、扭转算例上取得了 $4.4\times$ 的整体墙钟时间加速比。相较于同精度的单精度 FP32 三阶段基线，融合核函数依然在悬臂梁上带来 $2.3\text{–}4.6\times$、在扭转上带来 $2.8\times$ 的加速。在悬臂梁算子的真实 CUDA-event 独立测量中，单步加速比达到 $8.9\text{–}13.8\times$。

该性能飞跃由两个相互复合的核心机制共同驱动：
1. **显存流量物理消除（主机制）**：融合核函数避免了在阶段之间向板载 DRAM 写入和回读庞大的中间单元数组（`uelem` 与 `felem`），依据实测访存剖析模型，每次矩阵向量乘的有效 DRAM 负载降低了 $1.8\text{–}2.0\times$；同时单刚广播常驻共享内存，片上带宽复用高达 24 倍。
2. **API 调度与核函数启动开销消除（次机制）**：未融合的三阶段基线每次矩阵乘均需触发三次独立的底层 CUDA API 派发；而在 120 步拓扑优化中，累积的 CG 迭代步数可达数万次，这意味着数万次乃至十万次 API 派发的启动延迟被彻底消除，在 Python/CuPy 解释型环境中这一系统级收益尤为突出。

实测显存有效带宽表明，融合核函数达到了 61–179 GB/s 的有效带宽（占 1.008 TB/s 理论峰值的 6–18%），而 FP64 基线仅为 20–43 GB/s（占 2–4%）。两者均远低于 Roofline 脊点（81.9 FLOP/B），这从底层体系结构上坚实确立了算子处于深度带宽受限（memory-bound）区间的事实。

## 5.2 BF16 张量核心：前景与精度壁垒

在微观算子层级，张量核心展现出巨大的计算吞吐优势：在 512k 规模的独立 PyTorch BF16 GEMM 代理基准测试中，相较于双精度 DGEMM 录得了 $14.3\times$ 的惊人加速。然而，当把 BF16 算子嵌入整体的共轭梯度法（CG）求解器时，这一巨大的微观算力优势却遭遇了坚硬的数学精度壁垒。

根本原因在于 BF16 仅有 7 位尾数，其单位舍入误差 $\varepsilon_{\text{BF16}} \approx 3.9 \times 10^{-3}$ 极为粗糙。在线弹性拓扑优化中，刚度矩阵的条件数随着网格细化以及空洞区域低密度的存在而急剧恶化，实测初始条件数即在 $10^5\text{–}10^6$ 量级，条件数乘积 $\varepsilon_{\text{BF16}} \cdot \kappa(\boldsymbol{K})$ 达到 $10^3$ 量级，极度突破了保证收敛的 Carson–Higham 上限 256。此时，内层 BF16 算子所产生的截断噪声甚至超过了外层残差本身的量级，导致迭代重细化完全停滞在 $40\%$ 以上的巨大误差平台上。

这一实测结果对 Henry 等人 [22] 此前关于 BF16 迭代重细化可在“很大条件数范围”内普适收敛的乐观预期作出了重要的工程定界：对于高对比度、网格密集的结构工程 PDE 边值问题，BF16 无法直接作为黑盒内层 Krylov 求解器使用。

## 5.3 与既有实现的背景对比

- **对比 Träff 等人 (2023) [12] 的 Futhark 方案**：Träff 等人利用函数式编译器 Futhark 隐式生成融合核函数，并结合 SSOR 预条件几何多重网格实现了超大规模求解。本文的优势在于直接基于原生 Python/CuPy 技术栈，通过 80 行内嵌 CUDA C 实现融合，完全无需编译为独立外部二进制，与主流科学计算生态无缝互通，并首次提供了详尽的单算子带宽量化、功耗测量与 BF16 张量核心的数值界定。
- **对比 Wang 等人 (2025) TOP3D_XL [14]**：TOP3D_XL 采用 MATLAB 平台的无矩阵实现，系统阐述了 EbE 与共享单刚的技术优势。本文与之互补，展示了现代 GPU 架构上核函数融合对于消除 DRAM 瓶颈的决定性意义。
- **对比 PyTopo3D [58]**：PyTopo3D 依赖 CPU 稀疏直接求解器（PyPardiso），在 216k 单元下需运行 10 分钟以上；本文单卡 GPU 融合求解仅需 17.5 秒，实现了数十倍的实质性提速。

## 5.4 局限性

1. **简单 Jacobi 预条件子的迭代步数膨胀**：当前实现采用 Jacobi 对角预条件子，虽然易于无矩阵并行，但在剪切主导（如扭转算例）或长细比极大的几何域中，CG 收敛严重减缓，极易触碰预设的 1,000 步迭代上限；在存在准刚体模态的奇异工况（如未充分约束的 MBB 梁）下甚至无法保证物理有效性。
2. **原子累加操作的硬件依赖性**：融合核函数在 Scatter 阶段高度依赖全局 `atomicAdd`，其吞吐性能在不同微架构的 GPU（如数据中心 A100/H100 与消费级 RTX 4090）上可能存在吞吐差异。
3. **正交六面体规则网格假设**：当前基于片上共享内存单刚复用的极高加速比，严格依赖于结构网格下所有单元刚度矩阵几何全同的性质；对于非结构扭曲网格，单刚各异，需退化为通用低秩或数值积分格式。

## 5.5 通向几何多重网格集成的路径

克服当前预条件子差距并充分释放张量核心算力的最具前景的技术路径，是构建基于融合核函数的多重网格预条件共轭梯度法（MG-PCG）：
1. **多重网格作为条件数调节器**：在两层或三层几何多重网格（GMG）V-cycle 中，粗网格校正负责消除全局低频误差，使得传递至细网格平滑器的等效残差谱半径受到严格控制，其有效条件数可稳定压制在 256 以下；
2. **BF16 张量核心作为高效平滑器**：将本文实现的 BF16 WMMA 融合核函数作为多重网格中的 Chebyshev 或 Jacobi 多项式平滑器，在满足数值稳定性的前提下，充分榨取张量核心 $165.2 \text{ TFLOP/s}$ 的惊人算力；
3. **无矩阵层级间转移**：限制（Restriction）与延拓（Prolongation）算子在结构化八叉树网格上同样具备全无矩阵结构，可与平滑核函数进一步流水线融合。

# 6 结论

本文针对消费级 GPU（NVIDIA RTX 4090）上的无矩阵三维 SIMP 拓扑优化，提出了单一融合 Gather–GEMM–Scatter CUDA 核函数，并系统评估了 BF16 WMMA 张量核心变体的数值特性，取得如下主要结论：
1. **核函数融合显著打破访存瓶颈**：通过将单元 Gather、刚度 GEMM 与 Scatter 原子累加封装为单次遍历，中间临时数组完全驻留在寄存器与共享内存中，消除了两次 DRAM 往返。在悬臂梁实际算子上取得 $8.9\text{–}13.8\times$ 的单步 matvec 加速，并在 216k 至 4.9M 悬臂梁算例上实现了 $4.6\text{–}7.3\times$、扭转算例上实现了 $4.4\times$ 的端到端 SIMP-120 加速。
2. **能耗与计算效率大幅优化**：在 21.6 万和 100 万单元规模下，实测板卡功耗表明融合路径相比双精度 FP64 能耗降低达 $3.2\text{–}4.9\times$，GPU 平均运行功率仅占额定 450 W 的 29%–52%。
3. **揭示并实证了 BF16 张量核心在拓扑优化中的精度壁垒**：实测表明，尽管 BF16 张量核心可在局部 GEMM 上实现 $14.3\times$ 加速，但由于 SIMP 刚度矩阵条件数（$\kappa \approx 10^5\text{–}10^6$）严重超越理论阈值 256，BF16-IR 求解器出现严重的收敛停滞，明确否定了将 BF16 直接作为通用内层 CG 替代方案的可行性。
4. **指明了多重网格集成的关键后续方向**：指明将融合张量核心作为几何多重网格平滑器，是未来兼顾高鲁棒性、收敛性与硬件极致吞吐的最优架构方案。

# 附录 A 可复现性说明

本文全部定量基准数据均支持独立复现，实验细节与执行规范如下：
1. **硬件与驱动**：测试主机配置单张 NVIDIA GeForce RTX 4090（24 GB GDDR6X），主机 OS 为 Windows 10.0.26200.8037，NVIDIA 驱动版本 595.71。主板 PCIe 配置为 Gen4 x16。

3. **测试脚本与复现流程**：
   - 算子微基准：对每种网格尺寸预热 10 次迭代，随后连续采集 50 次迭代时间并求均值；
   - SIMP 优化基准：执行完整的 120 步设计循环，包含滤波与 OC 更新，各步自动记录墙钟耗时、柔顺度以及求解器残差历史；
   - 功耗测量：采用独立的硬件监控脚本在优化运行期间以 100 ms 间隔轮询 GPU 板卡功率，并计算累积能量积分（Wh）。

# 附录 B 指标约定与产物来源

1. **选定迭代步指标约定**：由于 SIMP 优化在后期施加高惩罚系数和陡峭 Heaviside 投影时，最后几步可能产生微小的数值震荡，本文主表中所汇报的最终柔顺度统一采用“选定最佳有效迭代步（Selected iterate）”，即在优化历程中体积分数偏差在 $\pm 1\%$ 以内的设计步中选取柔顺度最低值。
2. **预印本产物对应关系**：
   - 表 4 中的代表性单次运行数据均与随附的原始运行日志一一对应；
