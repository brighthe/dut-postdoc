# 任意次 Hu–Zhang 混合有限元拓扑优化投稿论文框架

> 本文件是面向 CICP 投稿的决策页，只维护论文定位、主张边界、最小证据和投稿门禁。详细公式与章节正文由 [[arbitrary-order-huzhang-topopt-draft-zh|中文稿]] 维护；博士论文第五章及其旧图、旧表和旧数值只作为历史线索，不能直接作为投稿证据。

## 一、论文定位

### 1.1 中心研究问题

在单纯形网格上，任意次 Hu–Zhang 对称应力混合离散能否形成一套数学一致、可实现且可验证的密度拓扑优化框架；它在不同阶次、复杂边界、近不可压缩材料和局部应力约束中能够提供哪些可靠性、精度与成本权衡？

论文以“问题或缺口 → 方法 → 可核查主张 → 公平比较 → 适用边界”为叙事主线。“任意次”“高精度”“抗闭锁”和“应力可靠”均为待验证能力，不作为预设结论。

### 1.2 CICP 投稿定位

首选目标期刊为 *Communications in Computational Physics*（CICP）。论文以任意次 Hu–Zhang 混合离散及其在密度拓扑优化中的一致计算框架为中心；近不可压缩和局部应力约束是验证方法价值的代表性问题，不与离散方法并列为独立主题。

数学性与计算力学性只决定 CICP 稿件内部的贡献排序：若形成可分析的方法增量，则强化假设、命题和数值分析；若主要证据来自困难力学优化问题，则强化计算模型、公平比较和适用边界。正式证据不足以支撑 CICP 时重新选刊，不通过包装旧结果维持既定目标。

期刊级别、积分和动态目录信息由 `repository:heliangos:career/dlut-postdoc/journal-strategy.md` 维护，本文件不复制。

### 1.4 写作与论断边界

- 当前维护中文稿；英文题目、摘要结论和结果讨论在正式证据完成后重写。
- $H(\mathrm{div})$ 协调性只保证内部面法向牵引单值，不表示完整应力张量跨单元连续。
- “无体积锁定”必须受离散稳定性、材料插值和求解精度假设约束；默认只报告所考察参数下的退化情况。
- 表观应力约束只避免特定密度分母型表达，不消除点载荷、尖角、重入角或几何退化造成的连续体应力奇异性。
- 未通过文献边界、公式核查和对应 acceptance 的主张不得进入摘要、贡献列表或结论。

## 三、拟定正文结构

叙事路线选定为「方法构造 + 充分数值证据」：数值章节保持完整的公平比较与独立复核，不压缩为纯正确性验证。这是篇幅与结构层面的决定，最终贡献排序仍按门禁 C 复核。

### 3.1 CICP 体裁约定

依据 CICP 官方 Guide for Authors（<https://www.global-sci.com/index.php/cicp/guide-for-authors>，核查日期 2026-08-07）与两篇同期刊范本：

- Chen, Chen, Huang & Wei, *Geometric Decomposition and Efficient Implementation of High Order Face and Edge Elements*, CiCP 35(4) (2024), 1045–1072，28 页；
- Chen, Chen, Gao, Huang & Wei, *Basis Construction for Smooth Finite Element Spaces*, CiCP (2026, 在审)，32 页。

固定以下约定：

- CICP 不规定章节结构。Guide for Authors 只覆盖 PDF 投稿、录用后交 LaTeX 源、版权转让与 `cicp.cls` 模板，另需在投稿时声明 AI 使用。章节架构属学科惯例，以上述范本为准。
- Front matter 顺序：Title → Authors 与编号脚注式 affiliations → Abstract → **AMS subject classifications** → **Key words** → 通讯作者 email 脚注。
- 引言末尾必须有 “The rest of the paper is organized as follows” 路线图段落。
- 复杂但机械的构造细节、完整差分表与次要消融放入 **Appendix**；不使用 Supplementary Material，CICP 无该常规通道。
- 实现平台按惯例在正文点名（两篇范本均引 FEALPy）。
- 两篇范本均无结论节。本文因含比较性结论与明确适用边界，保留结论节，但控制在一页以内。

### 3.3 §4 Implementation 的小节分工

本节主题句：**对 Hu–Zhang 元，自由度管理即法向迹连续性管理；角点部分松弛不是补丁，而是该管理规则的一个参数化选择。** 这是把 C2 从「若干技巧的拼装」提升为「一致实现框架」的依据。

| 小节 | 任务 | 交付物 |
|---|---|---|
| 4.1 网格数据结构与全局参考标架 | 定向约定；每个共享子单形上唯一的 $(\boldsymbol t^f,\boldsymbol n^f)$ 标架及其全局定向规则。Hu–Zhang 每个插值点挂一组对称矩阵基，而非 BDM/Nédélec 的单个向量，标架不一致会使同一全局自由度在两侧代表不同应力分量 | 约定 + 图 |
| 4.2 自由度的几何分解与全局编号 | $\mathbb N_f(\mathbb S)$ 分量跨单元共享、$\mathbb T_f(\mathbb S)$ 分量单元私有；顶点→（松弛附加）→边→单元内部的编号顺序；`cell2dof` 与按实体存储的 `nsframe`/`esframe`/`csframe` | $d=2$、$k=1{-}4$ 的显式计数表（含松弛后一行） |
| 4.3 基函数的直接全局标架构造 | 基函数直接在全局子单形标架下生成，未松弛时无局部→全局变换（变换矩阵为单位阵）；唯一非平凡块是松弛角点的 $4\times4$ | 公式 + 算法 1（自由度构建） |
| 4.4 角点松弛的自由度级实现 | 两单元可容性检验与分割边确定；$\mathbb N_e$/$\mathbb T_e$ 分量判定与四自由度归属；声明 $\boldsymbol\Sigma_{h,\mathrm{rel}}^k\subset H(\operatorname{div},\Omega;\mathbb S)$ 仍成立 | 算法 2 + 二联图 |
| 4.5 离散牵引提升的构造 | $\boldsymbol\sigma_{g,h}$ 由 $\Gamma_N$ 面自由度插值 $\boldsymbol g$ 的法向迹并零延拓，设计无关只算一次；区分右端 $-a_\rho(\boldsymbol\sigma_{g,h},\boldsymbol\tau_h)$ 每步重算与 $-b(\boldsymbol\sigma_{g,h},\boldsymbol v_h)$ 只算一次 | 公式 |
| 4.6 鞍点系统装配与优化循环复用 | 仅 $\boldsymbol A_\rho$ 依赖密度，$\boldsymbol B$、$\boldsymbol C$ 全循环装配一次；低阶 $\boldsymbol C$ 的面积分装配与 $\ell_h^D$ 一致性项；求解器、容差、计时与内存口径声明。`ldof` 与非零元随 $k$ 的实测增长移入 §6.2.1，本节只保留 §4.2 的解析计数 | 复用结构说明 |

> **已决（2026-08-07）**：角点松弛按 `soptx` 实际实现统一为**两单元、真实内部边**的构造——角点须恰好由两个单元包围、二者恰好共享一条与角点相连的内部边，该边即分割线；不引入虚拟分割线，不在单元内部重构子单元基函数。角点四个自由度 $(d_0,d_1,d_2,d_3)$ 中 $d_0,d_1$（$\mathbb N_e$-型）共享，$d_2,d_3$ 分别私有于两单元内截。[[../concepts/huzhang/huzhang-mixed-fem]] 第 3.4 节与 [[arbitrary-order-huzhang-topopt-draft-zh]] 第 3.4/4.4 节同步。
>
> **同批修正（同日，同一次 `soptx` 核对）**：
> - §4.1 的全局标架规则原写为"由顶点全局编号升序确定"，与实现不符。实际为：边标架取网格全局边的 $(\boldsymbol n_e,\boldsymbol t_e)$，单元标架取笛卡尔标架，顶点标架由关联边继承（边界顶点取边界边、松弛角点取分割边）。
> - §4.3 原设的"局部→全局基变换块"在实现中不存在：基函数直接在全局子单形标架下生成，未松弛时变换矩阵恒为单位阵；唯一非平凡块是松弛角点上的 $4\times4$。该小节已改题为「基函数的直接全局标架构造」。
> - §4.2 的 $\mathrm{ldof}_\sigma$、$\mathrm{eldof}$、$\mathrm{cldof}$、$\mathrm{gdof}_\sigma$ 公式与 $k=1{-}4$ 计数表已与实现逐项核对一致。

### 4.3 Evidence 状态

- `historical`：博士论文或 legacy driver 中的旧结果，只能帮助恢复参数。
- `development`：环境、revision 或 acceptance 尚未满足正式证据要求。
- `validated`：公式、配置和 acceptance 通过，但尚未在 clean revision 上形成完整 provenance。
- `formal`：clean revision 上重算，环境、参数、产物与 SHA-256 完整；只有此状态可进入投稿定量结论。
