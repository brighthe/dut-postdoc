# LLM Wiki 方法论与知识库架构模式

本仓库遵循 [Andrej Karpathy 提出的「LLM Wiki」模式](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)，在原始资料与研究者之间维护可追溯、可持续更新的 Wiki，使阅读所得与跨文献分析能够被后续研究复用。本页解释设计，不另设权限、页面格式或操作规程。

## 三层分工

- 原始源层提供最终事实依据，包括论文与其他原件。
- Wiki 层保存译文、概念、调研、研究判断与科研产出，通过来源引用区分证据和推论。
- Schema 层规定页面如何组织与维护，采用「单一事实源 + 多工具导入桩」架构：不同 AI 工具遵循各自约定的入口读取指令（如 Codex 与 OpenCode 直接读取 `AGENTS.md`，Claude Code 读取 `CLAUDE.md`，Antigravity 读取 `.agents/rules/`）；所有导入桩均通过轻量代理指向根目录 `AGENTS.md`（工具无关的常驻协作与行为规范单一事实源），杜绝规则漂移；page-schemas.md 集中页面结构与存储要求，templates/ 提供骨架，本页解释设计理由。

## 三类活动

| 活动 | 目的 | 常见产物 |
|---|---|---|
| Ingest | 把新资料中需要长期保留的信息整理进知识库 | 译文、概念补充、调研更新及来源引用；不必每份资料都全文翻译 |
| Query | 利用已有知识回答问题，辨析证据和不确定性 | 有来源的回答；有长期价值且获得相应授权时回填页面 |
| Lint | 发现知识与组织结构的问题 | 矛盾、过期、孤页、缺链和遗漏清单，以及授权后的修复 |

## 导航与维护

全库内容由根总导航（[[../index]]）提供领域入口，一级内容索引组织各主题页面，双链连接相关证据。索引服务于查找，不复制每页的研究进度；日志保留变更经过。具体层级与维护边界以规范入口为准。

研究者决定问题、路线与最终判断；AI 协助整理、核对和维护。知识的积累依赖可检查的来源与持续修订，不能靠文件数量或自动生成篇幅衡量。
