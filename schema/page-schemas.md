# 页面归属与结构规范

定义页面归属、结构、状态与来源要求；协作规则见 [[../AGENTS]]，写法见 templates/ 下的对应模板。

## 页面归属与模板

| 目录 | 职责 | 模板 |
|---|---|---|
| literature/ | 文献译文与证据；不另建单篇 notes 层，研究相关性写入 research/ | [[templates/translation-note]] |
| research/ | 研究计划、跨文献调研、技术指南、研究判断与申请材料 | 暂不设模板，按实际研究/调研内容组织 |
| entities/ | 人物、团队、机构、方法或软件档案及相关讨论、工作汇报 | 暂不设模板，按人物/讨论实际内容组织（结构为 `entities/<对象>/<对象>.md`） |
| concepts/ | 独立于具体研究项目仍成立的概念与数学基础 | [[templates/concept-note]] |
| papers/ | 自己撰写的论文提纲与正文 | 按论文实际要求组织 |
| talks/ | 准备中或仍需维护的报告、演示文稿与讲稿 | 按报告内容组织 |
| archive/ | 已完成且不再主动维护的事件材料 | 保留事件材料结构 |
| schema/ | 页面规范、方法论说明与模板 | 不套 Wiki 内容模板 |

实体档案使用 `entities/<对象>/<对象>.md`，相关汇报和讨论放在同一对象目录；人物关系由 `entities/relationships.md` 维护。报告与档案按英文 kebab-case 事件目录组织。工具配置与缓存目录不属于 Wiki 内容，不建立内容索引。

## 索引规则

- 根 index.md 链接上述七个内容目录及少量跨目录稳定入口；各内容目录仅在一级保留 _index.md，按主题直接收录子目录页面，不创建二级或更深的 _index.md。复杂主题可用 Guide、项目方案或事件 README 提供阅读入口。
- 一级索引采用 [[templates/directory-index]]：简述收录范围，再用“页面 / 入口、说明”两列表格导航。索引不复制具体页面的状态、进度或正文。
- 根导航不套目录模板，属性为 title、type: index、tags、status、date_added、date_update，正文为简短概述、领域导航和稳定入口。
- schema/、assets/、sources/、translations/ 不单独设索引；维护条件见 [[../AGENTS#导航与记录维护]]。

## 页面属性与状态

按模板真实填写属性；未知事实明确标注，不保留占位符，不适用的可选信息删除或使用有明确含义的空列表。字段写法和日期键见模板。无专用模板的 Wiki 页面至少填写 title、tags、status、date_added、date_update；已有页面沿用其含义相同的日期字段，不为统一字段名批量迁移。状态采用本页对应类型；未列出的指南、研究计划或报告使用 draft、in-progress、done 表示初稿、维护中和完成。来源按内容在属性或正文中如实标注。

| 页面 | 状态含义 |
|---|---|
| 概念、实体、调研 | draft：初稿；in-progress：维护中；done：本页内容已完成 |
| 索引 | in-progress 或 done，仅描述索引自身 |
| 译文 | draft：未完成；read：内容已整理、未完成逐页核验；done：已对照原始 PDF 完成逐页核验 |
| 工作汇报 | preparing：准备中；reported：已实际汇报；follow-up-done：后续行动已完成 |
| 论文 | outline：提纲；drafting：正文初稿 |
| 归档 | archived，并记录事件日期和归档日期 |

## 存储与来源

- iCloud 保存非论文原件与敏感材料，Zotero 保存论文附件，Git 保存 Wiki、模板、代码及适合公开复现的派生文件，不作为原件归档池；.gitignore 执行此边界。
- 原始资料只读，本地副本放所属目录 sources/，不入 Git，丢失后从主档重建。译文 source 写 `../sources/<basename>.pdf`，不写机器绝对路径。
- 其他原件使用 `<数据包>:<包内相对路径>`，由对应 sources.md 登记来源、必要哈希与 iCloud 相对路径。博士后原件路径从“博士后-大连理工大学”开始记录。
- 外部源码主档为 upstream Git，本地副本放所属 WSL 代码根，AI 只读、不修改或构建。引用使用 `<仓库名>:<仓库内路径>`，具体代码附 commit，由 literature/fem-libraries/sources.md 解析。
- Wiki 图件放所属方向 assets/，使用裸文件名嵌入；figures/ 用于论文、报告、档案的 LaTeX 交付树及带生成脚本的算例，与源码同级。根目录不设 assets/。

## 特定页面要求

### 概念页要求

- 写稳定知识；个人路线取舍、研究进度和待验证问题归入 research/ 或汇报页。
- 结构为 frontmatter、简短概述、按概念逻辑编号的正文和参考依据，不强套固定栏目；概述说明机制、作用与适用边界。
- 区分来源事实与本页推导。参考依据只列实际采用的来源并说明支撑内容；仅主题相关的链接放在正文，不另设“相关页面”节。

### 译文要求

文献文件使用 AuthorYear-short-topic basename，中文译文加 -zh；Citation Key 与文件名分离，记录在 frontmatter 的 citekey 和 literature/refs.bib。

- 原始 PDF 是核验依据，提取文本仅辅助。按原文章节与编号保留正文、图表、附录及参考文献，术语和引用体例忠实原文；疑似错误或冲突用译者脚注说明。
- 出版信息与 citekey 须核实，citekey 与 literature/refs.bib 一致；图表数据、单位与公式重构回看原页。
- done 的核验范围覆盖章节、公式、图表资产、脚注和来源。语法检查不代替原页核验，未核验内容不得称为全文已核验证据；交付说明报告核验范围与未解决问题，不添加译后检查清单栏目。
- 图题在图下、表题在表上，居中加粗写法见 [[templates/translation-note]]。公式保留 LaTeX；HTML 内公式的阅读视图限制如实说明，不自动替换成 Unicode。

### 工作汇报页面边界

- 汇报可独立阅读，区分文献结论、已有能力、本人增量，以及已完成、在推进和后续设想。
- 仅保留有日期与来源的必要快照和实际会后结论；原始沟通与行政记录由对应沟通仓库维护，项目实时状态以项目仓库为准，不建立并行事实账。

### 报告交付要求

- 源文件、PDF 与 Guide 保持一致，数值回到来源核验；发现版本不一致时先说明，不用旧文件覆盖当前成果。核心页 Guide 解释术语、公式、数据、来源与事实边界。
- 修改 LaTeX 报告后重新编译正式 PDF，检查受影响页面版式与新增 Overfull；仅修改 Guide 或规则无需编译。未编译或未视觉核验时如实说明，不把旧 PDF 当作新产物。

### 报告与事件归档生命周期

- 事件完成且不再主动维护后，先抽取长期有效知识，再将最终交付物与准备材料整体移入 archive/<event>/，填写归档状态及日期。
- 归档保留历史记录，不持续更新旧脚本、话术与阶段状态；活跃页面不把归档 Guide 当作当前事实源。
