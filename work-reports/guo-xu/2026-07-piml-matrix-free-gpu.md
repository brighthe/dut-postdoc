## 三、PIML × Matrix-Free × GPU 科研主线

### 3.1 PIML

PIML 这条线，我已经跑通了“局部密度 → 子结构静力缩聚 → 等效刚度 $K_s$ → 接口求解”的基本流程，并训练了一个极小 MLP 直接预测局部 $K_s$。目前两档算例的相对预测误差均值分别约为 $1.6\times10^{-3}$ 和 $8.2\times10^{-3}$。这两个数是局部等效刚度的预测误差，不是位移、柔顺度或最终拓扑误差。下一步重点是结构保持、误差传播、灵敏度和拓扑优化闭环。

### 3.2 Matrix-Free

关联内容：内部文档 [[../../research/technical-lines/matrix-free-research-guide]]；外部仓库 `xihe`、`mfleo`。

Matrix-Free 这条线，我已经实现了积分点上的 $B^TDBx$ 算子作用，不形成全局刚度矩阵，也不预先形成单元刚度矩阵。MatVec 与显式矩阵乘保持机器精度一致，Matrix-Free CG 也已经跑通。另有一套 EA/EbE 的分布式 Maxwell/UPML 原型（`xihe/matrix_free_3`），目前正在恢复运行环境与算例，正确性、收敛性和多进程一致性验证**尚未闭环**，还不能作为已完成结果汇报。下一步是先闭合这个算例，再提取可复用接口、迁移到三维线弹性，并接入精确子结构 $K_s$、Krylov 和预条件子。

### 3.3 GPU/HPC

GPU/HPC 这条线，当前 soptx 原型在 13.2 万自由度下，单次 GPU MatVec 相对 CPU 路径约有 $11.9$ 倍加速，内存估计从 42.1 MB 降到 4.0 MB；这只是单次算子作用，不是完整求解加速。另外，我编写的 `mfleo` 已完成 650 万自由度、单 GPU + 单 CPU 核条件下的端到端 CG，相对 `MFEM PA` 基线约有 $3.72$–$12.74$ 倍加速。这证明已有单 GPU、Krylov 和基础预条件的工程经验，但多 GPU、多 CPU 核协同及 GPU-aware MPI 尚未考虑，也还不是当前 PIML 融合结果。

### 3.4 三条技术线的融合

三条线的结合点是：PIML 提供局部子结构算子，Matrix-Free 负责在全局 Krylov 求解中按需计算算子作用，GPU 负责批量推理和局部作用加速。目前三方面分别已有基础，但还没有形成一体化系统。

近期第一步是先把 `xihe/matrix_free_3` 恢复、跑通并通过真残差门禁；随后提取 EA/EbE 分布式算子接口并迁移到三维线弹性；随后用精确 $K_s$ 打通子结构级 Matrix-Free，与显式缩聚矩阵做正确性对照，再建立 Krylov 和预条件基线；之后换入 PIML 预测的 $\widehat K_s$，检查结构性质、全局误差和求解收敛；最后做 GPU 批处理和端到端 profiling。“桌面电脑做到十亿细网格”作为长期目标，用来倒推近期的接口、算法和性能基线。

### 4.2 我的初步思考

科学计算中的模型选型不能只比较测试误差，还需要同时考虑：

1. 学习对象是形函数、$K_s$、局部场还是其他算子；
2. 输入是规则网格、坐标查询还是非结构网格；
3. 数据和精确标签的生成成本；
4. 对称、正定、刚体模态和能量一致性等物理约束；
5. 模型误差对 Krylov、灵敏度和优化收敛的影响；
6. CPU、GPU 和分布式部署成本。

可以先在同一个 PIML 局部等效算子任务上建立统一 benchmark：MLP 作为已有本地基线，DeepONet/operator learning 作为有团队文献依据但尚未本地复现的候选；CNN、GNN 等暂不预设结论。最终比较局部误差、结构保持、全局响应、求解器收敛和 GPU 性能，而不是直接选一个“最先进”的网络。
